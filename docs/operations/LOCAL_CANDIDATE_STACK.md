# Running a candidate build locally, beside the development stack

How the release candidate was run for author verification on 2026-10-02,
without touching the owner's running `droppilot` Compose stack, its
database volume, or its secrets.

## What is isolated, and how

| Concern | How |
|---|---|
| Source | `git archive <candidate-sha>` into a scratch directory — the main checkout and its branch are not touched, and an archive contains no `.env` |
| Containers, network, volumes | Compose project name `dp-candidate` (own network, own `dp-candidate_postgres_data` / `_rabbitmq_data`) |
| Ports | only nginx **18080** and the API **18000** are published; Postgres, Redis and RabbitMQ stay internal, so nothing collides with the owner's 80 / 8000 / 5432 / 6379 / 5672 |
| Queues | the project's own RabbitMQ — workers cannot consume the owner's (or any live) queue |
| Scheduled jobs | `beat` is not started |
| Secrets | the owner's existing root `.env` is passed by absolute path (`env_file` and `--env-file`), so the local-only encryption key is reused and no copy of any secret is made |
| Code in images | no bind mount of `./backend`; the API runs the built image without `--reload` |

## Override file (`candidate.override.yml`, kept outside the repository)

```yaml
services:
  postgres: { ports: !reset [] }
  redis:    { ports: !reset [] }
  rabbitmq: { ports: !reset [] }
  backend:
    env_file: !override ["C:/Projects/ds-platform/.env"]
    ports: !override ["18000:8000"]
    volumes: !reset []
    command: uvicorn app.main:app --no-proxy-headers --host 0.0.0.0 --port 8000
  worker:
    env_file: !override ["C:/Projects/ds-platform/.env"]
    volumes: !reset []
  beat:
    env_file: !override ["C:/Projects/ds-platform/.env"]
    volumes: !reset []
    profiles: ["never"]
  frontend:
    ports: !reset []
    build:
      args:
        NEXT_PUBLIC_API_URL: http://localhost:18080
        NEXT_PUBLIC_ENVIRONMENT: local
  nginx:
    ports: !override ["18080:80"]
```

## Commands

From the exported directory (`DC` abbreviates the Compose invocation):

```bash
DC="docker compose -p dp-candidate --env-file C:/Projects/ds-platform/.env -f docker-compose.yml -f candidate.override.yml"
$DC build backend worker frontend
$DC up -d postgres redis rabbitmq
$DC run --rm --no-deps backend alembic upgrade head
$DC up -d backend worker frontend nginx
```

Open **http://localhost:18080** and register. Without an AliExpress
connection nothing can be imported; for a walk-through, drafts can be seeded
with `frontend/tests/e2e/helpers/seed_drafts.py` (JSON on stdin; see the
script). Stop with `$DC down` — add `-v` only to discard this stack's own
database.

frontend scanned). In the browser: registration, Studio home listing seeded
drafts, preview generated by `StubProvider` (shown as "Test AI preview"),
approval ("Approved. Your draft and your Shopify listing are unchanged."),
