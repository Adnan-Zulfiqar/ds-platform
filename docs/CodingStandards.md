# Coding standards

Rules that are machine-checkable are enforced in CI. Everything else is a review
expectation. Where a rule exists to prevent a specific failure, the failure is
named — a rule without a reason gets ignored.

## Enforced automatically

| Check | Tool | Command |
|---|---|---|
| Python lint | Ruff | `ruff check .` |
| Python format | Ruff | `ruff format --check .` |
| Python types | mypy (strict) | `mypy app` |
| Python tests | Pytest | `pytest` |
| TS lint | ESLint | `npm run lint` |
| TS types | tsc | `npm run typecheck` |
| Frontend build | Next.js | `npm run build` |

A red pipeline is not merged. Suppressions (`# type: ignore`, `eslint-disable`)
require a comment explaining why — every one currently in the codebase names the
upstream library whose stubs are incomplete.

## Layer discipline

The single most important rule:

> **Handlers validate, delegate, and return. Nothing else.**

No SQL in a handler. No `fastapi` import in a service. No `HTTPException`
outside `app/api/`. `app/api/v1/users/router.py` is the reference.

Import direction is strictly one-way: `api → services → repositories → models`,
with `core` at the bottom depending on nothing.

## Python

**Type everything.** mypy runs in strict mode. `Any` requires justification.

**`from __future__ import annotations` at the top of every module.** Makes
annotations lazy, so forward references work without quoting.

**Keyword-only arguments for anything ambiguous at the call site.**
`Page.build(*, items, page, size, total_items)` — four positional integers would
be trivially transposable.

**Domain exceptions, never bare `Exception`.** Every raise carries a stable
`code`.

**Docstrings explain *why*, not *what*.** The signature already says what.

```python
# Useless — restates the code
def get_by_id(self, entity_id: UUID) -> Model | None:
    """Get an entity by its id."""

# Useful — records a decision
def get_by_id_or_raise(self, entity_id: UUID) -> Model:
    """Fetch by id, raising NotFoundError when absent.

    For a tenant-scoped repository, a row belonging to another tenant is
    invisible and therefore reported as not found. That is deliberate — a 403
    would confirm the id exists and enable enumeration.
    """
```

**No hardcoded values.** Anything environment-dependent belongs in
`core/config.py`. Anything reused belongs in a named constant.

## TypeScript

**No `any`.** Use `unknown` and narrow.

**`interface` for object shapes, `type` for unions and mapped types.**

**Server Components by default.** Add `"use client"` only when the file needs
state, an effect, an event handler, or a browser API.

**Never fetch in a component.** Go through `services/`, which owns the endpoint,
the query key, and the response type together.

**Server state in React Query, UI state in Zustand.** Never copy an API response
into a store.

## Database

- Every business table carries `tenant_id`, `created_at`, `updated_at`,
  `deleted_at` — inherit `TenantScopedBase` rather than assembling mixins.
- Never `DELETE`. Use `soft_delete()`.
- Every migration must have a working `downgrade()`. An un-reversible migration
  turns a bad deploy into an incident.
- Review every autogenerated migration by hand. Alembic misses enum changes and
  can generate destructive column drops for a rename.
- Index any column used in a `WHERE`, `JOIN`, or `ORDER BY` at scale, leading
  with `tenant_id`.

## Testing

**Test behaviour, not implementation.** A test asserting on internal call order
breaks on every refactor and catches nothing.

**Name the scenario, not the function.**

```python
# Bad
def test_create_user(): ...

# Good
def test_create_rejects_a_foreign_tenant_id(): ...
```

**Tenant isolation gets a test for every new tenant-scoped repository.** These
are the highest-value tests in the suite — a regression is a cross-tenant data
leak. They run without a database by inspecting compiled SQL, so there is no
excuse to skip them.

**Unit tests must not need Postgres, Redis, or the network.** Anything that does
goes in `tests/integration/` behind the `integration` marker.

## Security rules

Non-negotiable:

1. Never return an ORM model from an endpoint. Always a response schema.
2. Never interpolate user input into SQL. `sort_by` and filter fields are
   validated against per-model allowlists.
3. Never log a credential, token, or request body containing customer data.
4. Never trust a client-supplied tenant identifier once auth exists.
5. Never put a secret in a `NEXT_PUBLIC_*` variable — those are inlined into the
   client bundle.
6. Never `git commit` a `.env`.

## Git

Conventional Commits:

```
feat(products): add bulk import endpoint
fix(auth): reject expired refresh tokens
docs(architecture): record pagination trade-off
```

Imperative mood, present tense. The body explains *why* when the change is not
self-evident.
